# CodeCanopy GitHub Pages surface

## Scope and mode

Persuade. A small public landing page at `docs/index.html` for engineers evaluating the CodeCanopy Codex plugin.

## Audience, job, and action

The visitor is a software engineer deciding whether CodeCanopy offers a safer and more useful coordination model than simply spawning many agents. Within one viewport they must understand nested ownership, dependency-ready execution, bottom-up verification, and the smallest-tree principle. Primary action: copy or use the installation command. Secondary action: inspect the GitHub repository.

## Proof and content

Use only repository-backed facts: the v0.2 runtime contract, `.codecanopy.toml` defaults, Git isolation rules, and published installation command. Do not invent adoption metrics, customers, testimonials, audit logs, runtime enforcement, or provider support beyond Codex.

## Constraints

Static HTML and CSS under `docs/`; no runtime dependencies or required JavaScript. Responsive, semantic, keyboard accessible, and fast. No emoji, purple gradients, glow, glassmorphism, generic AI network imagery, or generic equal-card scaffolds.

## Direction

Air-traffic flight-progress-strip operations board. Pale cool-gray control surface, deep navy-black ink, paper-strip blue and pale green state fields, and safety orange used only for actions. Condensed industrial display lettering is paired with a neutral readable body face; monospace is limited to actual commands and configuration. The page is structured as a routed control surface rather than a conventional SaaS hero.

Approved composition: `.impeccable/mocks/codecanopy-route-a.webp`, explicitly approved by the user from the rendered image on 2026-08-21. Preserve its split first viewport: factual headline and actions on the left, nested progress-strip rack on the right, and one continuous operations band below. Replace every illustrative value with the actual v0.2 contract.

## Memorable moment

The first viewport makes the critical path physically legible: nested work strips are accepted bottom-up until one final `GOAL VERIFIED` strip clears. The primary install action sits on the same control surface.
